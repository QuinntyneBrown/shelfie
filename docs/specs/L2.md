# L2 - Detailed Requirements

Acceptance tests must carry a header comment such as `// Traces to: L2-001, L2-003` naming every L2 they cover. Viewport tiers: XS <576px, SM >=576px, MD >=768px, LG >=992px, XL >=1200px.

## L2-001: Reader PIN sign-in
**Traces to:** L1-001

The reader signs in by choosing her profile and entering a 4-digit PIN.

**Acceptance Criteria:**
1. Given the sign-in page, when the reader picks her profile and enters the correct PIN, then she is taken to her shelf.
2. Given a wrong PIN, when it is submitted, then an inline error is shown and the keypad clears.
3. Given five consecutive wrong PINs, when the fifth fails, then the keypad is locked for 5 minutes and shows the remaining time.
4. Given the keypad is locked, when the correct PIN is entered, then sign-in is still refused until the lock expires.
5. Given a PIN field, when non-digits are typed, then they are rejected and at most 4 digits are accepted.

---

## L2-002: Grown-up password sign-in
**Traces to:** L1-001

The grown-up signs in with e-mail and password.

**Acceptance Criteria:**
1. Given valid credentials, when submitted, then the grown-up lands on Review.
2. Given an empty or malformed e-mail or an empty password, when submitted, then field-level errors are shown and no request is sent.
3. Given wrong credentials, when submitted, then one generic "e-mail or password is wrong" error is shown that does not reveal which was wrong.
4. Given a submission in flight, when the button is pressed again, then no second request is sent and the button shows a busy state.
5. Given the server is unreachable, when sign-in is submitted, then an error state with a retry action is shown.

---

## L2-003: Session expiry
**Traces to:** L1-001

Sessions expire and the user is told why.

**Acceptance Criteria:**
1. Given a session with no activity for 30 days, when the user takes any action, then they are sent to sign-in showing the "expired" message.
2. Given a user signs out, when they press Back, then no protected data is displayed.
3. Given sign-out, when completed, then the server session is invalidated.
4. Given the account menu, when "Switch reader" is chosen, then the session ends and the profile picker is shown.

---

## L2-004: Forgot and reset grown-up password
**Traces to:** L1-001

The grown-up can request a reset link by e-mail and set a new password.

**Acceptance Criteria:**
1. Given any well-formed e-mail, when submitted on Forgot password, then the same success message is shown whether or not the account exists.
2. Given a valid single-use reset link, when a new password of at least 8 characters is submitted twice identically, then the password changes and the grown-up is signed in on this device.
3. Given a used or expired link, when opened, then an error state is shown with an option to request a new link.
4. Given mismatching or too-short passwords, when submitted, then inline errors are shown.
5. Given a reset completes, when finished, then all existing grown-up sessions are invalidated.

---

## L2-005: Route authorisation
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given no session, when any protected page or API is requested, then the user is sent to sign-in and the API returns 401.
2. Given a reader session, when Review, Books, Manage book or Settings is opened by URL, then the "Grown-ups only" page is shown and the API returns 403.
3. Given an unknown URL, when opened, then the Not found page is shown with a link home.
4. Given an unexpected server failure, when a page loads, then the Something went wrong page is shown with a retry action and no stack trace.

---

## L2-006: Household data isolation
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given two households, when household A requests an id belonging to household B, then the response is 404 and no data from B is returned.
2. Given a reader session, when she requests another book's chapter that is not in her household, then it is refused.

---

## L2-007: Reader shelf
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given books in different states, when the reader opens her shelf, then reading books, up-next books and finished books are shown with cover colour, sticker, title and progress.
2. Given no books, when the shelf opens, then an empty state tells her to ask a grown-up to add a book.
3. Given the shelf is loading, then skeleton placeholders are shown; given a load failure, then an error state with retry is shown.
4. Given XS, MD and XL viewports, when the shelf is shown, then the grid uses 1-2, 3 and 4+ columns respectively with no horizontal scroll.
5. Given 80 or more chapters, when a book card is shown, then progress renders without overflow.

---

## L2-008: Book page
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given a book, when opened, then chapters are listed with logged/not-logged state and review status.
2. Given a logged chapter, when its row is shown, then it displays the first line of her first answer instead of a title.
3. Given the next unlogged chapter, when the page is shown, then a primary "Log chapter N" action is visible without scrolling at XS.
4. Given a finished book, when opened, then the reward (if any) is shown.

---

## L2-009: Add a book
**Traces to:** L1-003

The reader or the grown-up supplies a title, an optional author, the chapter count, a cover colour and a sticker.

**Acceptance Criteria:**
1. Given valid input, when submitted, then the book appears on the shelf as "up next" and a success toast is shown.
2. Given an empty title, or a chapter count that is not an integer from 1 to 200, when submitted, then inline errors are shown and nothing is saved.
3. Given title or author longer than 120 characters, when typed, then input is limited to 120.
4. Given a failure, when submitted, then an error is shown and the entered values are kept.
5. Given a reader session, when she opens Add a book from her shelf, then the same form is shown and the book she adds appears on her shelf.

---

## L2-010: Manage and remove a book
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given a book, when the grown-up edits title, author or chapter count and saves, then the changes appear on the shelf.
2. Given the Remove dialog, when confirmed, then the book and its chapters, answers and feedback are deleted and a toast confirms.
3. Given the Remove dialog, when cancelled or Escape is pressed, then nothing is deleted and focus returns to the trigger.
4. Given a deletion failure, when confirmed, then the dialog shows an error and the book remains.
5. Given the Books list is empty, then an empty state offers "Add a book".
6. Given a book with N logged chapters, when the chapter count is set below N, then an inline error is shown and nothing is saved.

---

## L2-011: Log a chapter
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given the next chapter of a book, when the reader answers question 1 and presses "I'm done!", then the chapter is saved as waiting for review and a success state is shown.
2. Given question 1 is blank, when she submits, then an inline error is shown; given other answers are blank, then submission succeeds.
3. Given an answer over 2000 characters, when typed, then input is limited and a counter is shown.
4. Given a half-written log, when she leaves and returns on the same device, then her draft is restored.
5. Given a successful submission, when the success toast shows, then Undo within the toast's lifetime reverts the log; after it ends, answers are final and cannot be edited.
6. Given the last chapter is logged, when submitted, then the finished-book celebration (L2-019) is shown.
7. Given the same chapter already logged, when a second log is submitted, then it is rejected.
8. Given the read-date choice (Today, Yesterday, Another day), when she picks one, then that date is saved with the chapter; a date in the future is rejected.
9. Given a chapter other than the next unlogged one, when a log is submitted, then it is rejected.

---

## L2-012: View sent answers
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given a logged chapter, when opened, then the questions and her answers are shown read-only.
2. Given the chapter is awaiting review, then a "waiting for Dad" state is shown.
3. Given the chapter is reviewed, then the sticker and note are shown.

---

## L2-013: Default and custom questions
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given any book, when a chapter is logged, then the three default questions are shown in order and cannot be edited or removed.
2. Given Manage book, when the grown-up adds a question of 5 to 200 characters, then it is added to that book.
3. Given a question shorter than 5 or longer than 200 characters, when saved, then an inline error is shown.
4. Given a custom question is edited or removed, when saved, then only chapters logged afterwards use the change and earlier answers keep their original question text.
5. Given a save failure, when saved, then the dialog shows an error and keeps the text.

---

## L2-014: Review queue
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given chapters awaiting review, when the grown-up opens Review, then they are listed newest first with book, chapter and logged time.
2. Given none are waiting, then an empty "all caught up" state is shown.
3. Given a long queue, when shown, then it remains scrollable and usable at XS.
4. Given the tab bar, when at XS, then Review / Books / Settings appear as a bottom tab bar; at MD and above, in the top bar.

---

## L2-015: Review a chapter
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given a pending chapter, when opened, then the questions and answers are shown with sticker choices (Star, Wise owl, Rocket, Dragon, Cookie, Bright idea).
2. Given no sticker is chosen, when "Send" is pressed, then an inline error is shown and nothing is sent.
3. Given a sticker and an optional note of up to 300 characters, when sent, then the chapter becomes reviewed and the success state is shown.
4. Given an already reviewed chapter, when opened, then the sent feedback is shown read-only.

---

## L2-016: Reader sees feedback
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given new feedback, when the reader opens her shelf, then a banner announces it and links to the chapter.
2. Given the reader opens that chapter, then the banner no longer appears.

---

## L2-017: Give a reward
**Traces to:** L1-007

**Acceptance Criteria:**
1. Given a finished book without a reward, when the grown-up opens Give a reward, then four quick picks and a free-text field are offered.
2. Given an empty reward or one over 100 characters, when submitted, then an inline error is shown.
3. Given a valid reward, when submitted, then the book shows the reward and it appears on the trophy shelf.
4. Given a failure, when submitted, then the dialog shows an error and keeps the text.
5. Given a book that already has a reward, then no second reward can be given.

---

## L2-018: Trophy shelf
**Traces to:** L1-007

**Acceptance Criteria:**
1. Given rewards given, when the reader opens her shelf, then each reward is shown with its book and date.
2. Given a book is finished and unrewarded, then it appears as finished without a reward.

---

## L2-019: Finish-book celebration
**Traces to:** L1-007

**Acceptance Criteria:**
1. Given the last chapter is logged, when the success state is shown, then a celebration is displayed.
2. Given the user has reduced-motion set, then the celebration uses no animation.

---

## L2-020: Reading streak
**Traces to:** L1-008

**Acceptance Criteria:**
1. Given chapters logged on 5 consecutive days ending today, then the streak shows 5.
2. Given no chapter was logged yesterday or today, then the streak shows 0.
3. Given no chapter logged today but one yesterday, then the streak keeps its value.
4. Given the day boundary, then days are computed in the household's time zone.
5. Given the streak, then it is shown in the reader's top bar and to the grown-up, and cannot be edited.

---

## L2-021: Reader and grown-up settings
**Traces to:** L1-009

**Acceptance Criteria:**
1. Given Settings, when the grown-up changes the reader's name or avatar colour, or the grown-up's own display name, then it is reflected across the app.
2. Given a new 4-digit PIN, when saved, then the reader must use it on next sign-in.
3. Given a PIN that is not exactly 4 digits, when saved, then an inline error is shown.
4. Given a change to e-mail or password, when saved, then the current password must be provided and is verified first.
5. Given a save failure, then an error is shown and values are kept.

---

## L2-022: Appearance
**Traces to:** L1-009

**Acceptance Criteria:**
1. Given the choice "match device", when the device theme is dark, then the app renders dark.
2. Given "light" or "dark", when saved, then both users see that theme on every device.

---

## L2-023: Toasts and banners
**Traces to:** L1-010

**Acceptance Criteria:**
1. Given a completed action, when it succeeds or fails, then a toast with the matching severity is shown, announced by a live region, and dismissed after 8 seconds unless it has an action; the Undo toast after logging a chapter is the exception and lasts 10 seconds.
2. Given several toasts, then they stack with the newest nearest the edge.
3. Given a persistent condition such as offline, then a banner remains until the condition clears or the user dismisses a dismissible one.
4. Given hover or keyboard focus on a toast, then its timer pauses.
5. Given a danger toast, then it stays until dismissed or the retried action succeeds.

---

## L2-024: Offline behaviour
**Traces to:** L1-010

**Acceptance Criteria:**
1. Given the device goes offline, then an offline banner is shown and the previously loaded shelf remains readable.
2. Given a chapter is logged offline, then it is stored on the device and marked "will send".
3. Given connectivity returns, then queued chapters are sent in order and a toast confirms; a failed send remains queued.
4. Given an offline navigation to an unloaded page, then the Offline page is shown.

---

## L2-025: Responsive layout
**Traces to:** L1-011

**Acceptance Criteria:**
1. Given each page at 360, 768 and 1280 px widths, then there is no horizontal page scroll and no clipped controls.
2. Given dialogs under 640 px, then they appear as bottom sheets.
3. Given touch targets, then each interactive control is at least 44x44 CSS px.
4. Given the 16 px side gutter at XS, then content never touches the viewport edge.

---

## L2-026: Accessibility
**Traces to:** L1-011

**Acceptance Criteria:**
1. Given any page, when navigated by keyboard only, then every action is reachable in a logical order with a visible focus indicator.
2. Given a dialog opens, then focus moves into it and is trapped; on close focus returns to the trigger.
3. Given any text, then contrast is at least 4.5:1 (3:1 for large text) in both light and dark themes.
4. Given form errors, then they are associated with their field and announced to assistive technology.
5. Given prefers-reduced-motion, then non-essential animation is disabled.
6. Given an automated axe scan of each page, then no serious or critical violations are reported.

---

## L2-027: Credential and session security
**Traces to:** L1-012

**Acceptance Criteria:**
1. Given stored credentials, then passwords and PINs are stored only as salted, slow hashes (argon2id or bcrypt).
2. Given the session cookie, then it is HttpOnly, Secure, SameSite=Lax or Strict, and the token is rotated on sign-in.
3. Given state-changing requests, then a request without a valid CSRF defence is rejected.
4. Given repeated failed grown-up sign-ins from one source, then more than 10 attempts in 10 minutes are answered with 429.
5. Given responses, then CSP, X-Content-Type-Options, frame-ancestors and HSTS headers are set.

---

## L2-028: Input validation and output encoding
**Traces to:** L1-012

**Acceptance Criteria:**
1. Given any API input, then it is validated server-side for type, length and range, and invalid input returns 400 with field errors.
2. Given answers, notes or titles containing HTML or script, then they are displayed as text and never executed.
3. Given queries, then all database access is parameterised.
4. Given errors, then responses never expose stack traces, SQL or internal paths.

---

## L2-029: Data protection and privacy
**Traces to:** L1-012

**Acceptance Criteria:**
1. Given logs, then they never contain passwords, PINs, tokens or answer text.
2. Given the grown-up deletes a book, then its data is removed from the database.

---

## L2-030: Performance
**Traces to:** L1-013

**Acceptance Criteria:**
1. Given a mid-range phone on a 4G profile, then the shelf reaches Largest Contentful Paint within 2.5 s on a warm cache of 3 s or less cold.
2. Given 95% of API reads, then they respond within 300 ms at the server with 100 books of 80 chapters.
3. Given the initial JavaScript bundle, then it is at most 300 kB gzipped.

---

## L2-031: Data durability
**Traces to:** L1-013

**Acceptance Criteria:**
1. Given a submitted chapter, when the server responds success, then the answers survive a server restart.
2. Given a failed submission, then the reader's typed answers remain in the form and the draft.
3. Given a nightly schedule, then the database is backed up and a restore is documented.

---

## L2-032: Observability
**Traces to:** L1-013

**Acceptance Criteria:**
1. Given the API, then a health endpoint returns 200 only when the database is reachable.
2. Given each request, then a structured log line with request id, route, status and duration is written.
3. Given an unhandled error, then it is logged with the request id and the user sees only a generic message with that id.
