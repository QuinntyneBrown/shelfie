Theming

Light and dark are the same components reading the same token names; a theme is a block of semantic overrides applied with data-theme or the OS preference.

Overview

Shelfie ships a light and a dark theme. Both are the same components reading the same token names; only the semantic colour and shadow values change. The household picks "Match device", "Light" or "Dark" in Settings and it applies on every device for both of them.

How a theme applies

MechanismWhat it does
:rootLight values; the default.
[data-theme="dark"]Dark values on any element and everything inside it. Set on <html> when the household chose Dark.
@media (prefers-color-scheme: dark) on :root:not([data-theme="light"])"Match device": dark when the OS is dark, unless the household forced Light.
color-scheme: light | darkSet inside each theme so scrollbars, form controls and the default canvas match.
@media (prefers-contrast: more)Decorative borders become strong; muted and subtle text become default.
@media (forced-colors: active)Focus ring and borders hand over to system colours; key components draw a CanvasText border.
 
<!-- Match device: no attribute -->
<html lang="en">

<!-- Household chose Dark or Light in Settings -->
<html lang="en" data-theme="dark">
<html lang="en" data-theme="light">

The app sets the attribute before first paint (from the cached household setting) so there is no flash of the wrong theme. These docs and the mocks also accept ?theme=dark and the t key to preview.

Token tiers

TierExamplesWho reads itChanges per theme?
1 · Primitives--palette-violet-600, --font-size-md, --size-cover-mdOnly semantic tokensNo
2 · Semantic--color-accent, --text-body, --space-4, --radius-md, --shadow-1Components and pagesColour and shadow do
3 · Component--btn-bg, --field-border, --alert-icon, --cover, --avatar-sizeOne component; declared in components.cssNo; they alias semantic tokens

A theme overrides tier 2. A one-off re-skin of a single component overrides tier 3 in a scoped selector. Nothing outside tokens.css names a tier 1 token.

Adding a theme

  1. Copy the [data-theme="dark"] block in tokens/tokens.css and rename the selector, for example [data-theme="sunrise"].
  2. Point each --color-* token at a palette step. Add a new ramp under Primitives if the brand needs a hue the palette does not have; never put a raw value in the theme block (drift D1).
  3. Set color-scheme and, for a dark-based theme, --shadow-color and the four shadows.
  4. Keep the cover pastels and --color-fg-on-cover as they are; covers look the same in every theme.
  5. Run python3 .claude/skills/extracting-design-systems/scripts/check_contrast.py docs/design-system; every pair in contrast-pairs.json must pass in the new theme.
  6. Add the theme to the Appearance setting and to the docs' theme previews.

Consuming tokens.json

tokens/tokens.json is a DTCG export of tokens.css for tools that cannot read CSS (design tools, native shells, tests). Each token has $type, $value (an alias such as {palette.violet.600} or a raw value) and, under $extensions["com.agent-toolkit"], its CSS name, the resolved value and any theme overrides.

"accent": {
  "$type": "color",
  "$value": "{palette.violet.600}",
  "$extensions": {
    "com.agent-toolkit": {
      "css": "--color-accent",
      "themes": { "dark": { "$value": "{palette.violet.300}" } }
    }
  }
}
  • tokens.css is the source of truth; regenerate the JSON with scripts/tokens_to_json.py after every change and never edit it by hand.
  • In the Angular app, import tokens.css once in the global styles and read tokens with var(); components never import the JSON.
  • Playwright tests that need a value read it with getComputedStyle, so they follow the active theme.

Do and don't

  • Do read semantic tokens in components; don't read --palette-* outside tokens.css.
  • Do set data-theme on <html>; don't scatter it on individual components in the product (the docs use it on preview frames only).
  • Do check both themes for every new pair; don't assume a pair that passes in light passes in dark.
  • Do let prefers-reduced-motion, prefers-contrast and forced-colors adjust tokens; don't write theme-specific component CSS such as [data-theme="dark"] .card { … }.
