Accessibility

WCAG 2.2 AA in both themes, built in: 44px controls, one visible focus ring, plain-language errors, no time pressure and no motion for those who opt out.

Overview

Shelfie is built for a 9-year-old who is still learning to read, so accessible is not an extra: big targets, plain words, forgiving errors and no time pressure are the product. The system commits to WCAG 2.2 level AA in both themes. This page lists the commitments, the tokens that enforce them and how each component page proves them.

Perceivable

CommitmentWCAGRule in Shelfie
Text contrast1.4.3Body, label and secondary text at 4.5:1 or more on every surface it sits on, in both themes; large text at 3:1. Pairs live in tokens/contrast-pairs.json (82 pairs).
Non-text contrast1.4.11Field edges, the focus ring, meaningful icons, progress fills and selected-sticker edges at 3:1. Decorative dividers are exempt and documented as such.
Use of colour1.4.1Status is colour + icon + words; links are underlined; the next chapter says "Up next"; optional fields say "(optional)".
Resize and reflow1.4.4, 1.4.10All sizes in rem; every page reflows to 320px with no sideways scroll except tables inside .table-wrap.
Text spacing1.4.12Nothing breaks at 1.5× line height, 2× paragraph spacing, 0.12em letter spacing, 0.16em word spacing.
Images1.1.1Covers and stickers are decorative (aria-hidden) because the title or text beside them says the same; decorative SVGs are aria-hidden="true"; icon-only controls have aria-label.
Orientation and motion1.3.4, 2.3.3No orientation lock; every animation respects prefers-reduced-motion through the duration tokens.
Input purpose1.3.5autocomplete="email", current-password and new-password on the grown-up's fields.

Operable

CommitmentWCAGRule in Shelfie
Keyboard2.1.1, 2.1.2Everything works with Tab, Shift+Tab, Enter and Space, arrows in the account menu and radio groups, digits on the PIN pad. No traps; dialogs release on Escape.
Focus visible2.4.7One ring everywhere: 2px --color-focus-ring with a 2px offset on :focus-visible, at least 3:1 against what it sits on.
Focus not obscured2.4.11The sticky top bar, the tab bar and toasts never cover focus; scroll-padding-top matches the top bar.
Focus order2.4.3DOM order is visual order; no positive tabindex; dialogs move focus in (the safe button first in "Remove a book") and return it on close.
Target size2.5.8At least 24 × 24px (--target-min) for every target; 44px (--target-comfortable) for controls; small targets 8px apart or more.
Dragging2.5.7No drag interactions anywhere in Shelfie.
Timing2.2.1, 2.2.2Toasts last 8 seconds and pause on hover and focus; error toasts never auto-dismiss; confetti stops after 2.5s. The PIN lockout shows its countdown and Dad can reset it.
Skip and landmarks2.4.1A skip link to #main on every page; header, nav, main landmarks.
Titles and headings2.4.2, 2.4.6A unique <title> per page, one <h1>, headings in order.
Link purpose2.4.4Link text makes sense alone: "Back to my shelf", "See all chapters", "Review Chapter 10".
Pointer cancellation2.5.2Actions fire on click, never on pointer down.

Understandable

CommitmentWCAGRule in Shelfie
Labels3.3.2A visible label on every control; placeholders are never labels; optional fields say so in the label.
Errors3.3.1, 3.3.3Error text names the problem and the fix ("Use exactly 4 digits."); aria-invalid="true" plus aria-describedby; a summary ("Fix 2 things") links to each field and receives focus on submit.
Error prevention3.3.4Removing a book is confirmed in a dialog whose default is "Keep the book"; a sent chapter can be undone from its toast.
Redundant entry3.3.7Drafts autosave; the e-mail is remembered on the device; a failed save keeps everything typed.
Accessible authentication3.3.8Nia uses a 4-digit PIN with an on-screen keypad, no puzzles. Dad's password field allows paste and password managers.
Consistent navigation3.2.3, 3.2.4Same components, same order and same names on every page; each icon means one thing.
Language3.1.1<html lang="en"> on every page.
On input3.2.2Picking a sticker, a colour or a radio never submits or navigates by itself. The PIN pad is the one exception and says so: it submits on the fourth digit, as people expect from a keypad.
Help3.2.6Help text sits under the field it explains, in the same place on every form.

Robust

CommitmentWCAGRule in Shelfie
Name, role, value4.1.2Native elements first (button, a, input, details, dialog); ARIA only to fill gaps, following the WAI-ARIA Authoring Practices pattern named on each component page.
Status messages4.1.3Toasts in role="status"; errors in role="alert"; PIN progress announced as "2 of 4 digits entered".
Valid HTML—No duplicate ids; no interactive element inside another.

Targets and controls

2
Control heights sm 36px, md 44px, lg 52px. The count badge is the smallest target-sized element at 24px.

Focus

The ring is an outline, not a shadow, so it survives forced-colours mode (where it becomes Highlight). Text fields draw it with no offset and also colour their border, so the ring hugs the field. Menu items show focus as the hover background instead, because the menu panel is already a clear container.

Component contract

Every component page's Accessibility section answers the same seven questions:

  1. Role and pattern: the native element or WAI-ARIA Authoring Practices pattern used.
  2. Keyboard: a table of keys and what they do.
  3. Focus: where focus starts, where it goes on close, how the ring looks.
  4. Labelling: what is labelled, how, and what is announced.
  5. Contrast: the token pairs involved, measured live in both themes.
  6. Motion: what moves and what happens under reduced motion.
  7. Touch: target sizes and the alternative to any hover.

Testing

  • scripts/check_contrast.py for every pair in both themes.
  • scripts/check_design_system.py for labels, names, alt text, landmarks, headings and links.
  • Tab through every example on a component page; nothing is skipped, nothing traps.
  • A screen reader on one dialog (Remove a book), one form (Log a chapter) and one table (Books).
  • Zoom to 200% and 400%; emulate prefers-reduced-motion, prefers-contrast: more and forced-colors: active in Chrome DevTools.
  • Playwright acceptance tests assert accessible names and roles through page objects, in Chromium.
