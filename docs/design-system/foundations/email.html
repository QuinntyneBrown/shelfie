Foundation · E-mail

E-mail

The three mails Shelfie sends share one layout, rendered by the API from the tokens below as tables and inline styles. They are the only Shelfie markup built outside the components library.

WCAG 2.2 AAFoundationLight only

Overview

Mail clients strip <style> blocks, custom properties, web fonts, flex and grid, and most ignore dark-mode CSS. So an e-mail cannot read tokens.css: it carries the token values, resolved from the light theme, inline on each element. apps/api/src/mail-template.ts is the only place those values are written.

  • One template, three mails: verify your e-mail (L2-144), reset your password (L2-004) and the parent invite (L2-034). Each fills the same slots: a heading, one or two paragraphs, one button with its link, and a footer line saying why the mail came. See the e-mail mocks.
  • One column, 560px at most and fluid below, so the same mail reads on a phone and a desktop with no media queries.
  • Light only. The canvas and card set their own background, so a client that darkens text still keeps it readable.
  • Always a plain-text part with the same words and the bare link (L2-151).
  • Sent from Shelfie <hello@shelfie.kids> (ADR-0019).

Seven values, each a light-theme token resolved to hex. Every text pair passes 4.5:1.

Type

Mail clients cannot load fonts, so the stack is the token's rounded system stack without the web font, ending in Arial: ui-rounded, 'SF Pro Rounded', 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif. Sizes are pixels, because rem means nothing in most clients.

Spacing and shape

Padding comes from the 4px scale in pixels: 32px around the column and inside the card (--space-8, 24px sideways, --space-6), 16px between paragraphs (--space-4), 24px under the logo and around the button (--space-6). The card has the 24px card radius (--radius-lg) and the button is a pill (--radius-full, written as 999px). Clients that drop border-radius show square corners, which is acceptable.

The button

A bulletproof button: a one-cell table whose cell carries the colour as both bgcolor and background-color, holding a link padded to a 48px target. It works with images off and in Outlook, and stays a real link for screen readers. Exactly one per mail; its label says what happens ("Confirm my e-mail", "Choose a new password", "Create my account"). The same URL is repeated as text under it for clients that break the button.

Confirm my e-mail
The verify mail's button in the same table structure; here it reads the tokens, where the API writes their hex values from the colour table above inline. See the verify mock for the literal markup.

Logo

The logo mark (logo.png) sits centred above the card at 56 × 56 with alt="Shelfie", so the mail still says who it is from with images off. It is fetched from APP_URL/logo.png, the file the web app already serves; it is never attached or inlined as data.

Footer

Under the card, centred, muted caption text in two lines: why this mail came and what to do if it was not wanted ("If it wasn’t you, ignore this e-mail and nothing happens."), then Shelfie · Reading, one chapter at a time · shelfie.kids linking to https://www.shelfie.kids. No unsubscribe link: every mail is a single transactional message someone asked for. No tracking pixels and no tracked links.

Plain text

The plain-text part is the heading, the paragraphs, the bare link on its own line, the footer line and Shelfie · https://www.shelfie.kids, each separated by a blank line. It never has markup or a "view in browser" link.

Code

The API builds every mail with one function; the transport (apps/api/src/mail.ts) sends both parts.

renderMail({
  heading: 'Confirm your e-mail',
  paragraphs: ['Hi Marcus, welcome to Shelfie! …'],
  button: { label: 'Confirm my e-mail', url },
  footer: 'You got this because a Shelfie account was made with this address. …',
}) // → { html, text }
