Foundation · Motion

Motion

Quick, purposeful motion with a little spring for the reader’s big moments, all of it switched off when the device asks for reduced motion.

WCAG 2.2 AAFoundation

Overview

Motion in Shelfie explains what changed (a dialog rises from where it will sit, a toast slides in from its corner) and adds a little joy at the right moments (a springy sticker, confetti when she finishes a book). It is quick, never blocks input and switches off when the device asks for less motion.

  • Use a duration token and an easing token together; never a raw ms value or a named CSS easing.
  • No animation on page load except skeleton shimmer, with one documented exception: the auth page effects.
  • Animate opacity, translate, scale and rotate; avoid animating layout.

Durations

Each dot travels the same distance with --ease-standard; only the duration changes. Under reduced motion they jump.
TokenUse
--duration-instantState changes that must not animate
--duration-fastHover and colour changes, button press, chip and sticker selection, menu open
--duration-baseToast enter and leave, backdrop fade, accordion icon
--duration-slowDialog and sheet enter, progress bar fill
--duration-deliberateCelebrations; confetti runs five of these (2.5s) then stops
--duration-loopOne cycle of a looping indicator

Easing

Same 320ms, four curves. Spring overshoots and settles.
  • Standard for things that move within the page: progress fills, hover lifts, the accordion.
  • Enter (decelerate) for things arriving: dialogs, sheets, menus, toasts.
  • Exit (accelerate) for things leaving: a dismissed toast.
  • Spring only for playful feedback on her actions: sticker choices.

Loading loops

Saving draft
Loops share --duration-loop (1400ms): skeleton shimmer and pulse run one cycle per loop, the spinner runs twice as fast (drift D3).

Choreography

  • Dialogs fade the backdrop (base) and slide the panel up from the bottom on phones or scale in from 96% from 640px (slow, enter).
  • Toasts slide up 16px into place (base, enter); the newest enters at the bottom and older ones move up. Leaving, they fade and drop 8px (base, exit). The timer bar shrinks over the 8 seconds a toast stays.
  • Menus scale in from the corner nearest their trigger (fast, enter).
  • Celebrations: confetti falls for 2.5s once, then stops; the heading never waits for it.
  • Nothing moves on its own after a page has settled except a loading indicator and the auth page effects.

Auth page effects

This is the one place the system animates on page load. Auth pages (sign in, sign up, accept invite) are the only pages seen cold, so they get a short welcome. All of it stops under prefers-reduced-motion.

  • Card entrance: scale-in over --duration-slow with --ease-enter.
  • Field stagger: class .stagger on the form, with a --i custom property on each child. Each child uses slide-up, delayed by calc(var(--i) * var(--duration-fast) / 3).
  • Logo sway: .sticker--bob uses the bob keyframes, looping over --duration-loop x 3.
  • Aurora: a full-bleed <canvas class="aurora"> behind the card, painted by WebGPU (assets/aurora.js). It reads the five --color-cover-* tokens, re-reads them on theme change, draws at 55% strength in light and 32% in dark on a half-resolution canvas, and pauses when the tab is hidden. Without navigator.gpu it falls back to the CSS gradient class .aurora--css (keyframes aurora-drift). Under reduced motion it is only the static gradient.

Reduced motion

Under prefers-reduced-motion: reduce, tokens.css sets every duration to 0.01ms, so transitions and entrances become instant without any component change. components.css also stops loops after one pass, turns off the skeleton shimmer and hides the confetti. The button spinner still shows (as a static ring) because it tells her something is happening.

  • No animation flashes more than three times a second (2.3.1).
  • Smooth scrolling is turned off too.
  • Test with DevTools: Rendering → Emulate CSS media feature prefers-reduced-motion.

Usage

  • If a motion does not explain a change or celebrate her progress, remove it.
  • Never delay input behind an animation; a dialog's buttons work while it is still easing in.
  • Keep spring for the reader's moments; the grown-up screens use standard and enter only.
