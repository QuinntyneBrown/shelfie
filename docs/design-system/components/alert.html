Alert and banner

An alert is a tinted box that stays where it is until the situation changes: "The book wasn’t saved", "Dad hasn’t read this yet". A banner is the same component stretched across the top of every page for news about the whole app.

Overview

Use an alert for a message about one form, dialog or page that must stay visible while the person deals with it. Use a banner (.alert.banner) for a message about the whole app that should follow them from page to page. For news about something that just happened and needs no action, use a toast; for a problem with one field, use an inline message.

  • Info: neutral news. "Dad read Chapter 9 and gave you a Star", "You were signed out".
  • Success: something good to see once. "Saved", "Dad gave you a reward for Matilda".
  • Warning: things work, with a catch. "No internet connection", "Let’s take a short break".
  • Danger: something failed. "Shelfie isn’t reachable right now", "The reward wasn’t saved".

Anatomy

  1. Status icon20px, --alert-icon, aria-hidden.
  2. Title.alert__title: the message in one line.
  3. Text (optional)A plain <div>: what it means, what to do.
  4. Actions (optional).alert__actions: a link or a small button.
  5. Dismiss (optional).close, 24px, for messages that are only news.
  6. ContainerStatus tint, hairline border with a 4px leading edge, --radius-md, 16px padding.

Variants

Four statuses. A bare .alert is info.

Review assistant

Review a chapter uses the existing statuses for the assistant; no new variant. Warning marks an answer to talk about (title "Talk about this", the reason as its message) and sums the flags up in the feedback card ("2 answers to talk about"); success says "Every answer looks good"; info carries the "Suggested note" with a small "Use draft" action, and "The assistant isn’t set up"; danger is "The assistant couldn’t help this time" with "Try again". All text is shown as plain text.

I loved how you noticed Edmund starting to feel sorry. That was really thoughtful!

Sizes

One size. Alerts take the width of their container; banners take the width of the screen.

  • Dismissible: only alerts that are pure news (a reward, "Dad read Chapter 9") get a close button. Alerts about a problem go away when the problem does.
  • Persistent: the review-queue banner shows on every grown-up page except Review itself, until the queue is empty. The offline banner stays until the connection returns, then becomes the "Back online" toast.

Responsive behaviour

  • Alerts are fluid; text wraps and actions wrap below the text.
  • Banners below 640px stack title, text and actions in a column, left aligned. From 640px they centre and put them on one row that wraps if needed.
  • Banners push the page down; they never overlap content or the top bar.

Theming

Each status sets four component tokens, --alert-bg, --alert-fg, --alert-border and --alert-icon, from the semantic --color-{status}-bg/-fg/-border/-icon. Themes change the semantic tokens; in the dark theme the tints turn deep and the text light. The dismiss hover is currentColor mixed at 8%, so it follows the status.

.alert--warning { --alert-bg: var(--color-warning-bg); --alert-fg: var(--color-warning-fg);
                  --alert-border: var(--color-warning-border); --alert-icon: var(--color-warning-icon); }

Accessibility

Role and pattern

WAI-ARIA status and alert roles. Info, success and warning use role="status" (polite). Danger uses role="alert" (assertive). A form summary adds tabindex="-1" and receives focus on submit. Render the alert into the page when the event happens; an alert already in the HTML at load is read in page order, not announced.

Keyboard

KeyAction
TabReaches the action, then Dismiss, in reading order.
Enter, SpaceFollows the link, runs the button, or dismisses.
Enter on a summary linkMoves focus to the field with the error.

Focus

Alerts do not move focus, except the form summary, which takes focus after a failed submit. After Dismiss, focus moves to the next focusable element after where the banner was (the first link in main).

Labelling

The icon is aria-hidden; status is said by the title. Dismiss is named "Dismiss". Links say where they go: "Open Chapter 9", "Review Chapter 11".

The border is decorative; status is carried by icon, title and tint together.

Motion

None. Alerts appear in place.

Touch

Dismiss is a 24px target pulled into the corner; small action buttons are 32px tall inside a full-width row.

Content

  • Title says what happened, plainly: "The reward wasn’t saved", not "Error 503".
  • Text says what was kept and what to do: "What you typed is still here."
  • For Nia, be kind and never blame: "Let’s take a short break", "Ask Dad if you’ve forgotten it."
  • Form summary title: "One more thing" for a single error; each item names the question.
  • Action labels are verbs: Try again, Try now, "Open Chapter 9".
