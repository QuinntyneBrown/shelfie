Component · Inputs

Text field

A single-line input for the short things Shelfie asks for: a book title, a chapter count, a reward, an e-mail address, a password.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Put .input on a native <input> and wrap it in a form field for its label, help and error. Use a textarea when the answer can run to more than one line, and a radio group when the answer is one of a few known options.

The mocks use five input types, each with the right keyboard and autofill hints:

  • Text: Title, Author, Name, The reward.
  • E-mail: E-mail address, with autocomplete="email".
  • Password: autocomplete="current-password" to sign in, new-password to change it.
  • Number: chapter counts, with inputmode="numeric", min and max.
  • Date: "Pick the day" inside the "Another day" chip on Log a chapter.

Nia's own 4-digit PIN is set by Dad in Settings with a password input (inputmode="numeric", maxlength="4"); Nia types it on the PIN keypad, not in a text field.

Anatomy

  1. LabelFrom the form field; always visible.
  2. Value--text-body (16px) in --color-fg-default. No placeholder.
  3. Container--field-bg and --field-border, --radius-md, hairline border, --control-height-md tall.

Variants

One look; the type, inputmode and autocomplete attributes do the work.

E-mail, password, number and PIN, as in Sign in, Add a book and Settings.
HTML
<input class="input" id="email" type="email" autocomplete="email" required>
<input class="input" id="password" type="password" autocomplete="current-password" required>
<input class="input" id="chapters" type="number" inputmode="numeric" min="1" max="200" required style="max-width: 8rem;">
<input class="input" id="pin" type="password" inputmode="numeric" pattern="[0-9]{4}" maxlength="4" autocomplete="off">

Sizes

Medium is the default. Large is for the one field a page is about (the title on Add a book). Small fits a field inside a chip.

Small 36px (.input--sm, --font-size-sm), medium 44px, large 52px (.input--lg, --font-size-lg).

Both themes

  • Invalid adds a --color-danger-solid border plus an inset ring, so the edge reads as 2px without shifting layout. Always paired with a .field__error.
  • Read-only is what every field becomes while its form is submitting: the value stays visible, selectable and focusable on a sunken background.
  • Disabled is used only for the date input inside a chip while saving, where the chip itself is disabled too.

Responsive behaviour

  • Inputs are width: 100% of their field. Inline max-width caps hint at the expected length: 8rem for numbers and the PIN, 16rem for names, 24rem for the e-mail.
  • The value is 16px at every width, so no browser zooms the page on focus.
  • Numbers and the PIN bring up the numeric keypad on phones through inputmode="numeric".

Theming

Two component tokens carry every state: --field-bg (default --color-bg-surface, read-only --color-bg-surface-sunken, disabled --color-bg-subtle) and --field-border (default --color-border-strong, hover --color-fg-muted, focus --color-focus-ring, invalid --color-danger-solid). The textarea shares both.

/* Each state only reassigns the two tokens */
.input:read-only:not(:disabled) { --field-bg: var(--color-bg-surface-sunken); }
.input[aria-invalid="true"] { --field-border: var(--color-danger-solid); }

Accessibility

Role and pattern

Native <input> with the right type; the browser provides the textbox, spinbutton or date picker role. Labelled by a <label for> in a form field, or aria-label when the visible label is the surrounding chip ("Pick the day").

Keyboard

KeyAction
Tab / Shift+TabMoves focus into and out of the field. Read-only fields stay in the tab order; disabled ones leave it.
↑ / ↓ in a number fieldSteps the chapter count by one within min and max.
EnterSubmits the form.

Focus

The border turns --color-focus-ring and the shared ring is drawn with no offset, hugging the box. Focus moves to the first field on auth pages and dialogs (autofocus), and to the error summary after a failed submit.

Labelling

Every input has a visible label. Use autocomplete for Dad's own details so password managers and autofill work (WCAG 1.3.5, 3.3.8): email, current-password, new-password. The PIN Dad sets for Nia uses autocomplete="off" so it is not saved as his password. Names of other people (Nia's name) get no autocomplete.

Disabled text is exempt from contrast minimums; it is only used while a form saves.

Motion

Border colour and ring transition over --duration-fast; zeroed under reduced motion.

Touch

Medium inputs are 44px tall and large are 52px. The small date input sits inside a 36px chip whose whole label is tappable.

Content

  • No placeholders. A hint belongs in .field__help, where it stays visible.
  • Pre-fill what is known: Manage book opens with the title, author and chapter count; Settings with the names and e-mail.
  • Keep what was typed after an error; only the person changes it.
  • Mask passwords with the browser's own masking; do not echo them anywhere else on the page.
