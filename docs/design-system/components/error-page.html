Error page

When a whole page cannot be shown, Shelfie replaces it with a big friendly sticker, a plain heading, one or two sentences and a way back to somewhere useful. Nobody should feel they broke something.

Overview

Use an error page when the route itself fails. There are exactly four. When only one section of a page fails, keep the page and use an error empty state in that section instead.

  • Page not found 🔍: a link is old, or the book was removed.
  • Grown-ups only 🔒: Nia opened a Review or Books link, or a grown-up opened another household's link.
  • Something went wrong 🛠️: the server failed. Shows a short code to mention.
  • Offline 📡: no connection and nothing cached for this page; paired with the offline banner.

The page keeps the normal top bar (and the tab bar on Dad's pages), so navigation still works.

Anatomy

  1. Sticker.sticker--xl (96px) in place of the empty-state icon; decorative.
  2. HeadingThe page's <h1 class="empty__title">, set in the h2 size.
  3. Explanation.empty__text: what probably happened and that nothing is lost.
  4. Way back.empty__actions: home for this person, plus Try again or Sign out where it helps.

Variants

Four pages, one layout. The examples use <h2>; in the product the heading is the page's <h1>.

    <h1 class="empty__title">You’re offline</h1>
    <p class="empty__text">Shelfie will reconnect by itself. …</p>
    <div class="empty__actions"><button class="btn btn--primary" type="button">…Try again</button></div>
  </div>
</main>

Sizes

One size: the page-scale empty state with an extra 64px above it so the message sits in the upper middle of the screen.

States

Each error page is a single state. Its buttons carry the interactive states; Try again becomes a loading button while it retries.

Responsive behaviour

  • Centred in main at every width; the text stops at 36ch.
  • On phones the two actions wrap onto two centred rows; on grown-up pages the tab bar stays at the bottom.
  • The sticker stays 96px on all screens; it is the friendly part.

Theming

Reads the same tokens as the empty state plus --color-accent-subtle for the sticker circle. The heading uses --text-h2. Nothing is theme specific.

Accessibility

Role and pattern

A normal page: skip link, top bar, main with one <h1>. The document <title> names the problem ("Page not found · Shelfie") so it is announced on load. The server should answer with the matching HTTP status (404, 403, 500).

Keyboard

KeyAction
TabSkip link, top bar, then the page actions in order.
Enter, SpaceRuns Try again; follows the links.

Focus

On a client-side route change to an error page, focus moves to the <h1> (with tabindex="-1") so the heading is read first.

Labelling

The sticker is aria-hidden. The heading carries the whole message in words. The error code is plain text so it can be read out or copied.

Content

  • Headings are friendly and plain: "We can’t find that page", "This part is for grown-ups", "Something went wrong on our side", "You’re offline".
  • Say nobody is in trouble and nothing is lost: "Nothing you did caused this and nothing was lost."
  • Give the code only on the server error page, as something to mention: "mention code SHF-4F2A".
  • The way back is personal: "Back to my shelf" for Nia, "Go to Review" for Dad.
  • The forbidden page has a grown-up version: "That book belongs to another family."

Code

<main id="main" class="container">
  <div class="empty" style="padding-top: var(--space-16);">
    <span class="sticker sticker--xl" aria-hidden="true">🛠️</span>
    <h1 class="empty__title" style="font: var(--text-h2);" tabindex="-1">Something went wrong on our side</h1>
    <p class="empty__text">Nothing you did caused this and nothing was lost. …</p>
    <div class="empty__actions">
      <button class="btn btn--primary" type="button">…Try again</button>
      <a class="btn" href="/review">Go to Review</a>
    </div>
  </div>
</main>
Class / attributeEffect
.empty + padding-top: var(--space-16)Page-scale empty state.
.sticker.sticker--xl96px sticker in place of .empty__icon.
h1.empty__title + font: var(--text-h2)The page heading at h2 size.
tabindex="-1" on the h1Lets the router move focus to it.

components.css has no page-scale modifier, so the extra top space and the heading size are still set inline with tokens, as in the mocks.
