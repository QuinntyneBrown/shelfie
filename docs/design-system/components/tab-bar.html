Component · Navigation

Tab bar

Dad's navigation on a phone: three tabs pinned to the bottom of the screen, within thumb reach. From 768px it hides and the same three links move into the top bar.

WCAG 2.2 AAStatus: stableNative <nav> of links

Overview

Use the tab bar on every grown-up page: Review, Review a chapter, Books, Manage a book, Settings. It is the phone form of the top bar nav, with the same three destinations in the same order. Nia's pages never have a tab bar; she has one place to be.

  • Tabs are links, not ARIA tabs: each one goes to a different page.
  • The page wrapper gets .has-tabbar so the last content is not hidden behind the bar.
  • In these docs, .tabbar--static renders the bar in the flow of the page at every width.

Anatomy

  1. Barnav.tabbar, fixed to the bottom, --layout-tabbar-height (64px) plus the safe-area inset, surface background, top hairline.
  2. Icon24px (--size-icon-lg), aria-hidden.
  3. LabelOne word in --text-caption, medium weight; the accessible name.
  4. Count badge.badge--count pinned to the icon's top right; only on Review, only when something is waiting.

Variants

One variant, three tabs. What changes is which tab is current and whether Review has a count.

Sizes

One height, --layout-tabbar-height (64px) plus env(safe-area-inset-bottom); tabs share the width equally.

Responsive behaviour

  • Base (phones, up to 767px): fixed to the bottom at --z-sticky, full width, three equal tabs. Padding includes env(safe-area-inset-bottom) so it clears the home indicator.
  • .has-tabbar on the page wrapper adds bottom padding of --layout-tabbar-height + --space-6, so the last card and form actions stay reachable.
  • From 768px (--layout-breakpoint-md) the bar is display: none and .has-tabbar drops its padding; the top bar nav appears. .tabbar--static is exempt so these docs can show it.
  • Toasts sit above the bar on phones (toast region bottom offset).

Theming

The bar mirrors the top bar: --color-bg-surface with a top hairline in --color-border-default. Tabs read --color-fg-muted, --color-fg-default on hover and --color-fg-accent when current; the badge reads the danger-solid pair. Dark theme swaps only those tokens.

Accessibility

Role and pattern

A native <nav aria-label="Primary, phone"> of links with aria-current="page". Not the APG Tabs pattern: these change the page, so they are links and use plain Tab navigation. Only one primary nav is ever rendered visible (the other is display: none), so screen readers meet one navigation landmark.

Keyboard

KeyAction
Tab / Shift+TabMoves through Review, Books, Settings. The bar comes last in DOM order, after the page content.
EnterFollows the link.

Focus

The shared ring on the whole tab. Because the bar is fixed, .has-tabbar padding keeps the focused field above it (WCAG 2.4.11, focus not obscured).

Labelling

The visible word is the name; icons are aria-hidden. The count badge has its own aria-label ("2 chapters to review"), so the link reads "Review, 2 chapters to review, current page".

Motion

None. The bar does not slide or hide on scroll.

Touch

Each tab spans a third of the screen width and at least 44px (--target-comfortable) of the 64px bar, the largest targets on the grown-up pages.

Content

  • Same three words as the top bar, in the same order: Review, Books, Settings.
  • One word per tab; a label that wraps at 360px is too long.
  • The badge shows a number only; its spoken label says what the number counts.
