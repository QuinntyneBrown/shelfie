Table

A table lines up the same few facts for every row so they can be compared down a column. Shelfie uses one: the chapters Nia has logged for a book, on Manage a book.

WCAG 2.2 AAStatus: stableNative <table>

Overview

Use a table when the reader compares one column across many rows: which chapters still need review, when each was read. If each row is a single thing with a name and a line of context, use a list instead; it reads better on a phone. Nia never sees a table; tables are for the grown-up's pages only.

  • Framed (.table-wrap): a table on its own on the page, with a border and rounded corners.
  • Flush (.table-wrap--flush): a table inside a .card--flush; the card supplies the frame.

Anatomy

  1. Header cell<th scope="col"> on --color-bg-surface-sunken, --text-label in muted ink, sticky to the top of the wrapper.
  2. Body cell--text-body-sm, 12 × 16px padding, hairline divider below.
  3. Status cellA badge or a link; never colour alone.
  4. Wrapper.table-wrap scrolls sideways when the table is wider than the screen; border and --radius-lg unless flush.

Variants

Pick the wrapper by where the table sits. Inside a flush card use --flush so there are not two frames.

Sizes

One size: --text-body-sm with 12 × 16px cell padding. There is no dense or roomy variant; Shelfie's tables are short.

  • Loading: the card shows skeleton lines while the page loads (manage-book/loading); the table is never drawn with blank rows.
  • Empty: no mock shows a book with no logged chapters, so there is no empty table state. Leave the card out rather than draw a header with no rows.
  • Rows are not selectable and the table does not sort; chapters are always newest first.

Responsive behaviour

  • The table never squeezes. Below its natural width, .table-wrap scrolls sideways inside the card; the page itself never scrolls sideways.
  • td.truncate caps long text at 20rem with an ellipsis so one long answer cannot make every row wide.
  • Header cells do not wrap (white-space: nowrap) and stay stuck to the top of the wrapper when it scrolls vertically.
  • On phones, keep the table to four or five short columns; anything longer belongs in a list.

Theming

Reads --color-bg-surface (wrapper), --color-bg-surface-sunken (header), --color-bg-subtle (row hover), --color-border-default (dividers) and the muted and default ink. In dark mode the sunken header is darker than the surface, so the header still reads as a separate band.

Accessibility

Role and pattern

A native <table> with <thead>, <tbody> and <th scope="col">. It is a static table, not the APG grid pattern: no arrow-key navigation, no role="grid".

Keyboard

KeyAction
Tab / Shift+TabMoves between the links in the table, row by row.
EnterOpens the focused chapter.
Screen reader table keysMove by cell; each cell is announced with its column header.

Focus

Only links take focus, with the shared ring. A scrolling .table-wrap is reachable because the links inside it are; when a table has no links, give the wrapper tabindex="0", role="region" and an aria-label so keyboard users can scroll it.

Labelling

Every table has a <caption>; it may be visually hidden when a visible heading says the same. An empty header cell above links still has a visually hidden label ("Open"), and each "Open" link adds the chapter in hidden text so the link list reads "Open chapter 11".

Motion

None. Row hover is an instant colour change.

Touch

"Open" links sit in a cell with 12px vertical padding, giving a row of about 48px. Hover highlighting is a pointer nicety only; nothing depends on it.

Content

  • Column headers are one or two words in sentence case: "Chapter", "Read", "What happened", "Review".
  • Dates match the rest of the app: "Today, 4:12 pm", "Yesterday", "Tue 13 Oct".
  • Status is a badge with a word ("To review", "Reviewed"), never a coloured dot alone.
  • The caption says what the rows are and whose they are: "Chapters Nia has logged for this book".
