Empty state

What a page shows when there is nothing to list yet, or when its data could not load: a round icon, a short title, one sentence, and the one thing to do next.

WCAG 2.2 AAStatus: stableComposition

Overview

Use an empty state in place of a list or a page body that has no content: her shelf before the first book, Dad's review queue when it is clear, a section that failed to load. It always offers a way forward.

  • Empty (.empty): nothing here yet, and that is fine. Accent icon.
  • Error (.empty.empty--error): this part of the page didn't load. Danger icon and Try again.
  • Whole-page problems (page not found, offline, grown-ups only, server error) use the same classes at page scale; see error page.
  • For a failed action, not a failed load, use an alert or a toast.

Anatomy

  1. Icon.empty__icon: 64px circle, accent-subtle (danger-bg for errors), 32px line icon, aria-hidden.
  2. Title.empty__title: an <h2> in the h3 style; says what is (not) here.
  3. Text.empty__text: one or two sentences, muted, 36ch max.
  4. Actions.empty__actions: one primary action, optionally one secondary.

Variants

Nothing to review

You’ve read everything Nia has logged. New chapters show up here the moment she finishes them.

See her books

Your answers didn’t load

They’re safe on the server; we just couldn’t fetch them right now.

Back to the book
Empty: the review queue is clear. Error: the chapter page failed to load.
HTML
<div class="empty empty--error">
  <div class="empty__icon"><svg class="icon icon--lg" aria-hidden="true" viewBox="0 0 24 24">…</svg></div>
  <h2 class="empty__title">Your answers didn’t load</h2>
  <p class="empty__text">They’re safe on the server; we just couldn’t fetch them right now.</p>
  <div class="empty__actions">
    <button class="btn btn--primary" type="button">…Try again</button>
    <a class="btn" href="/books/lion-witch-wardrobe">Back to the book</a>
  </div>
</div>

Sizes

One size inside a page. The page-scale version, with a large sticker and the page heading, is the error page.

States

The block itself is static; its buttons and links carry the interactive states (see button). What changes is which variant shows and which actions it offers.

  • Retrying: Try again becomes a loading button (aria-busy="true"); on success the real content replaces the whole block.
  • Examples here use <h3> because this page already has its headings; in the product the title is an <h2> under the page's <h1>.

Responsive behaviour

  • Centred at every width, with 48px top and bottom and 24px sides.
  • Text stops at 36 characters wide so it never runs the width of a desktop.
  • Two actions sit side by side and wrap, centred, when they don't fit.

Theming

The empty icon reads --color-accent-subtle with --color-fg-accent; the error icon --color-danger-bg with --color-danger-fg. Title and text read --color-fg-default and --color-fg-muted on the page canvas. All are theme tokens; nothing in the component changes between themes.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and native buttons or links. No ARIA role. When it replaces content after a failed load, the page's live region (or the alert role on the retry result) announces the change; the block itself is not a live region.

Keyboard

KeyAction
TabMoves to the primary action, then the secondary.
Enter (and Space on buttons)Runs the action.

Focus

Focus does not jump to the empty state. After Try again fails, focus stays on the button.

Labelling

The icon is decorative. The title is a real heading, so it shows in the heading list. Retry is a <button> (it is an action); "Back to the book" is a link (it goes somewhere).

Motion

None.

Touch

Actions are medium or large buttons (40–48px) with 12px between them.

Content

  • Title says what is here, not what is missing in the abstract: "Your shelf is empty", "Nothing to review".
  • Text says why it is fine, or what is safe: "Your books and answers are safe; try again in a moment."
  • The action is the next step, in the reader's words: "Add my first book" (Nia), "See her books" (Dad).
  • Errors never blame the reader and never show codes in a section; codes belong on the server error page.
