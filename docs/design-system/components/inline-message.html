Inline message

One line of text right next to the thing it is about. A field error tells someone how to fix one answer; an inline status tells Dad his change is saving, then saved.

WCAG 2.2 AAStatus: stablearia-describedby / role="status"

Overview

  • Field error (.field__error): under one input, textarea or PIN, after a submit finds a problem with it. Pair it with a form summary when a form has more than one field.
  • Inline status (.inline-status): beside a card title while a change saves in place, "Saving…" then "Saved just now". Use a toast instead when the save takes the person somewhere else.

Do not use either for news that is not about the element beside it; that is an alert or a toast.

Anatomy

  1. Error glyph⚠ from .field__error::before; the text, not the glyph, carries the message.
  2. Error textSmall body text in --color-danger-fg, linked to the field with aria-describedby.
  3. Status dot.dot, 8px, currentColor; .dot--pulse while saving. Decorative.
  4. Status text"Saving…" muted; "✓ Saved just now" in success colour.

  • Field error appears after submit, never while typing; it clears once the field is valid on the next submit.
  • Saving… shows the pulsing dot until the server answers; then Saved just now replaces it in the same element, so it is announced once.

Responsive behaviour

  • Field errors wrap under the field at every width; the glyph stays on the first line.
  • Under the PIN dots the error is centred to line up with the keypad.
  • An inline status sits at the end of the card's title row (.cluster--between) and wraps under the title on a narrow card.

Theming

Field errors read --color-danger-fg; inline status reads --color-fg-muted, or --color-success-fg with --success. The dot is currentColor, so it always matches the text. All three are tuned per theme to stay above 4.5:1 on cards, the page and dialogs.

Accessibility

Role and pattern

A field error is plain text tied to its control with aria-describedby, with aria-invalid="true" on the control (WCAG 3.3.1). An inline status is a role="status" live region that exists before the save starts, so the change of text is announced politely.

Keyboard

KeyAction
TabMessages are not stops. Focusing an invalid field reads its label, then its error.

Focus

On a failed submit focus moves to the form summary, or to the only invalid field when there is just one. The inline status never takes focus.

Labelling

Put the error id first in aria-describedby, before the help text, so the problem is read first. The ⚠ comes from CSS content and some screen readers read it as "warning sign"; the sentence still makes sense with it. Wrap the ✓ in "Saved" in aria-hidden so it is not read as "check mark".

Motion

The dot pulses once per --duration-loop (1.4 s). Under reduced motion it runs one cycle and stops; the word "Saving…" still says what is happening.

Touch

No targets.

Content

  • Errors say how to fix it, not what is wrong in the abstract: "Enter a number from 1 to 200.", "Use exactly 4 digits."
  • For Nia, encourage: "Write a sentence or two about what happened. There are no wrong answers!"
  • Name the thing when it helps: "Type the book’s title. It’s on the front cover."
  • Status: "Saving…" (with the ellipsis character), then "Saved just now".
