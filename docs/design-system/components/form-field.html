Form field

The field wraps one control with everything around it: a visible label, an optional marker, help text and an error message that says how to fix it.

WCAG 2.2 AAStatus: stableNative <label>

Overview

Every text field and textarea sits inside a .field. The field stacks its parts in a fixed order: label, help, control, error. It has no look of its own beyond spacing and type.

  • Required is the default. Only optional fields are marked, with <span class="optional">(optional)</span> inside the label. The mocks mark 31 optional fields and no required ones.
  • Help (.field__help) says why the field exists or what a good answer looks like. It sits above the control so it is read before typing.
  • Error (.field__error) replaces nothing; it is added below the control when the value is wrong, and says how to fix it.

For a group of radios use a fieldset and legend instead (radio group). For a group of swatches, the field's label is a <span class="field__label" id> that the role="radiogroup" points at with aria-labelledby (swatch picker).

Anatomy

  1. Label<label class="field__label" for>, --text-label, always visible.
  2. Optional marker.optional, regular weight in --color-fg-subtle.
  3. Help (optional).field__help, --text-body-sm in --color-fg-muted.
  4. ControlAn .input or .textarea.
  5. Error (when invalid).field__error in --color-danger-fg with a ⚠ glyph, so colour is not the only cue.

HTML
<div class="field">
  <label class="field__label" for="reward">The reward</label>
  <div class="field__help" id="reward-help">Nia sees this on her shelf next to the book.</div>
  <input class="input" id="reward" type="text" required aria-invalid="true"
         aria-describedby="reward-error reward-help">
  <div class="field__error" id="reward-error">Tell Nia what the reward is.</div>
</div>

Sizes

The field takes its control's size; label, help and error text do not scale.

States

The field's state is its control's state, plus the error text when invalid. Focus and hover are forced on the control with data-state.

  • Errors appear after a submit attempt, never while typing; they clear when the field is next changed.
  • An invalid field keeps the value that was typed, so a typo can be fixed rather than retyped.

Responsive behaviour

  • The field is full width of its container on phones. Short answers are capped so the box hints at the answer's length: chapter counts and the PIN at 8rem, names at 16rem, the e-mail at 24rem.
  • Label, help and error wrap freely; nothing truncates.
  • Fields stack in a single column. The only side-by-side pair is "New password" and "Type it again" in Settings, which shares a two-column .grid.

Theming

The field reads --color-fg-default (label), --color-fg-subtle (optional marker), --color-fg-muted (help) and --color-danger-fg (error). All four are re-mapped by the dark theme; the field itself has no component tokens. The gap between parts is --space-1.

Accessibility

Role and pattern

Native <label for> tied to the control's id. Help and error are tied with aria-describedby, error first, then help: aria-describedby="chapters-error chapters-help". An invalid control sets aria-invalid="true".

Keyboard

KeyAction
Tab / Shift+TabMoves between controls; label, help and error are not focusable.
Error-summary linkMoves focus straight to the field; see form layout.

Focus

Focus is shown on the control, not the field. Clicking or tapping the label also focuses the control.

Labelling

Every control has a visible label (WCAG 3.3.2). Shelfie uses no placeholders, so nothing disappears when typing starts. "(optional)" is part of the label text and is read with it.

Motion

None. Errors appear without animation.

Touch

The label is part of the target: tapping it focuses the control, which helps small fingers on narrow fields like the PIN.

Content

  • Labels are short nouns or the question itself: "Title", "E-mail address", "How many chapters?", "What happened in this chapter?".
  • Help says why or how, in one sentence: "Count them in the contents page. You can change this later."
  • Errors say how to fix it, not what went wrong in system terms: "Enter 11 or more. Nia has already logged 11 chapters." Never "Invalid value".
  • Errors Nia sees are kind and reassuring: "Write a sentence or two about what happened. There are no wrong answers!"
  • "(optional)" in brackets, lower case, after the label.
