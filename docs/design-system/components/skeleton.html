Skeleton

Grey shapes in the layout of the page that is coming, with a soft shimmer. They show where things will be, so the page does not jump when the data arrives.

WCAG 2.2 AAStatus: stablearia-busy on the container

Overview

Use skeletons for the first load of a page or section whose layout is known: the shelf, a book, the review queue, a chapter. Keep the real page chrome (top bar, breadcrumb, page title, buttons that work without data) and swap only the data for skeletons.

  • For an action in progress, use a loading button or an inline status, not a skeleton.
  • If loading fails, replace the skeletons with an error empty state.

Anatomy

  1. Cover block.skeleton.cover: the cover's exact size and 2:3 shape, shimmer instead of colour.
  2. Title bar.skeleton--title: 1.5em tall, 40% wide.
  3. Text lines.skeleton--text: 1em tall; the last line is 60% wide.
  4. Busy containerThe real card with aria-busy="true" and an aria-label that says what is loading.

Variants

Pick the shape that matches what will replace it.

Title, text lines, block (a feedback note), covers small / medium / large.
HTML
<span class="skeleton skeleton--title" aria-hidden="true"></span>
<span class="skeleton skeleton--text" aria-hidden="true"></span>
<span class="skeleton skeleton--rect" style="height: 6rem;" aria-hidden="true"></span>
<span class="skeleton cover cover--sm" aria-hidden="true"></span>

Sizes

Text and title skeletons are sized in em, so they follow the font size of where they sit. Blocks take a height that matches the real content (6rem for a feedback note, 3.25rem for the hero's large button). Cover skeletons reuse .cover--sm, the default and .cover--lg.

States

A skeleton has one state, loading. The container moves from loading to loaded (or to an error).

Both themes

  • Loaded: remove aria-busy and the aria-label, and swap skeletons for content in one paint, so screen readers read the finished section once.
  • Failed: replace the whole section with an error empty state ("Your shelf didn’t load").

Responsive behaviour

  • Skeletons live inside the real layout (grid, cards, hero), so they reflow exactly as the content will.
  • Show the number of placeholders that fills the first screen: two book cards on the shelf, two rows in the review queue. Do not draw a whole list.
  • Fixed widths (a subtitle line of 16–18rem in the mocks) must stay below 320px wide so they do not overflow a phone.

Theming

The shimmer is a gradient between --color-bg-subtle and --color-bg-subtle-hover, both tuned per theme, so skeletons are quiet grey on light cards and a lifted grey on dark ones. .cover.skeleton drops the cover's shadow and colour.

Accessibility

Role and pattern

Every skeleton is aria-hidden="true". The section that is loading carries aria-busy="true" and an aria-label ("Loading your shelf", "Loading review queue"), so assistive tech knows it is not ready and does not read half a page.

Keyboard

KeyAction
TabSkips skeletons. Real controls in the chrome (Add a book, the breadcrumb) stay reachable while the data loads.

Focus

Skeletons never take focus. When content arrives, focus stays where it was.

Labelling

The busy container says what is loading in words. Keep the page <h1> real ("Hi Nia 👋", "Chapter 9") so the page is identified from the start.

Contrast

Skeletons are decorative placeholders and are exempt from 1.4.11. The real text that replaces them uses the normal pairs:

Motion

The shimmer runs once per --duration-loop (1.4 s). Under prefers-reduced-motion the animation is removed and the skeleton is a flat grey shape.

Touch

No targets.

Content

  • The busy label is "Loading" plus the thing: "Loading your shelf", "Loading review queue", "Loading your answers".
  • Never put text inside a skeleton or show "Loading…" over it; the shapes are the message.
