List

A list stacks rows that share one shape: a leading cover or number, a title, a short meta line and at most one or two actions. It is how Dad sees the review queue, every book and the questions for a book.

Overview

Use a list when each row is one thing with a name and a line of context, and the reader scans down to pick one. Use a table when people compare the same columns across rows (chapter, date, review status). Use an activity feed for things that happened, newest first. Use book cards on Nia's shelf, where each book deserves a bigger tile.

  • Review queue: chapters waiting for Dad, each with a Review button.
  • Books: every book with a status badge and a Manage button.
  • Questions: the questions Nia answers for a book, with icon-only Edit and Remove buttons.

A list usually sits flush inside a card (.card.card--flush) so the row dividers run edge to edge.

Anatomy

  1. Leading cover or numberA small cover (.cover--sm, 44px) or a question number. Decorative, aria-hidden.
  2. Title.list__title, --text-label. The thing's name.
  3. Meta.list__meta, --text-body-sm in --color-fg-muted. One line of context.
  4. Trailing badge and actionOptional status badge, then a small button or link.
  5. Row.list__item: flex row, 12 × 16px padding, 12px gap, hairline divider except on the last row.

Variants

There is one list. What changes is what sits at either end of the row; pick the leading element by what the row is about.

Sizes

One size. Row height follows its content: a 44px small cover plus 12px padding top and bottom gives a 68px row, comfortably above the 44px touch target. Do not shrink the padding to fit more rows; a long list scrolls.

States

The row itself is not interactive, so it has no hover, focus, active or disabled state; those belong to the button or link inside it (see button). The list's own states are about its content.

  • Loading shows two or three skeleton rows of the same shape inside the card, with aria-busy="true" and an aria-label such as "Loading review queue" on the container (see skeleton).
  • Empty replaces the whole card with an empty state that says why and offers the next step.
  • Long lists (14 chapters after a week away) stay one list, newest first, with a .badge--count next to the heading. No pagination below 50 rows.

Responsive behaviour

  • The row is a single flex line at every width. .list__body has min-width: 0 so the title wraps (or truncates) instead of pushing the action off screen.
  • At 360px a row with a cover, a badge and a button still fits: titles wrap to two lines. Add .truncate to the title only when the full text is available elsewhere (a title attribute or the page it links to).
  • Trailing actions never wrap under the body; if two buttons do not fit, make them icon-only with aria-label.

Theming

The list reads --color-border-default for dividers, --color-fg-default for titles and --color-fg-muted for meta. It has no background of its own, so it takes the card's surface in both themes. Covers keep their pastel and dark sticker in dark mode; see book cover.

Accessibility

Role and pattern

A native <ul> of <li>, so screen readers announce "list, 5 items". No ARIA role. Loading placeholders use <div class="list__item"> inside an aria-busy container, not list items, so nothing is announced until the real rows arrive.

Keyboard

KeyAction
Tab / Shift+TabMoves between the actions in each row, in reading order. Rows themselves are not focus stops.
Enter / SpaceActivates the focused link or button.

Focus

Only the actions take focus, with the shared ring. A row never gets tabindex.

Labelling

Wrap the list in a <section aria-labelledby> pointing at its heading ("Waiting for you"). Repeated actions name their row: visible text "Review" is fine when the row title sits just before it in reading order; icon-only buttons need "Edit question 4". The cover is aria-hidden because the title already names the book.

Row dividers use --color-border-default; they are decorative grouping, so 1.4.11 does not apply.

Motion

None. Skeleton rows shimmer on --duration-loop and stop under prefers-reduced-motion.

Touch

Small buttons (32px) sit at the row's end with 12px between neighbours; the row is at least 68px tall, so a thumb cannot hit the wrong row.

Content

  • Title first, the thing's real name: "Chapter 11 · The Lion, the Witch and the Wardrobe", "Matilda".
  • Meta is one line of the most useful context, joined with " · ": author and progress ("C. S. Lewis · 11 of 17 chapters"), or who and when ("Nia read it today, 4:12 pm").
  • Relative dates for this week ("today", "yesterday"), short dates after that ("Tue 13 Oct").
  • Newest first wherever time matters; the most urgent row gets the only primary button.

Class / attributeEffect
.listOn a <ul> or <ol>: removes bullets and spacing, stacks rows.
.list__itemOne row: flex, padding, divider (none on the last row).
.list__bodyThe flexible middle; min-width: 0 lets text wrap or truncate.
.list__title / .list__metaName and one line of context.
.truncateOne line with an ellipsis; pair with a title attribute.
