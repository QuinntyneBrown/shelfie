Component · Status

Badge

A small pill that labels a status in one or two words: "Reading", "Reward to give", "Reviewed". The count form shows how many chapters are waiting for Dad.

Overview

Use a badge to tag a row or heading with its status so Dad can scan a list or table. A badge is never clickable. If the reader can choose it, it is a chip; if it explains something, it is an alert or inline message; Nia's reading streak has its own streak pill.

  • Neutral (default): nothing needs doing yet. "Not started", or a plain count next to a heading.
  • Info: in progress. "Reading".
  • Warning: waiting on Dad. "Reward to give", "To review".
  • Success: done. "Rewarded", "Reviewed".
  • Count: how many things wait for Dad, in the nav and the tab bar.

Anatomy

  1. Dot8px circle in currentColor, drawn by ::before. A second cue besides the tint; hidden on count badges.
  2. Label--text-overline: small, uppercase, wide tracking.
  3. Pill--radius-full, 24px tall (--target-min), 8px side padding, status tint.

Variants

Pick by what happens next, not by how important the row is. Shelfie has no danger badge: nothing in a list is ever an error.

Sizes

One size: 24px tall. A count badge is at least 24px wide so a single digit makes a circle.

States

Badges are not interactive, so there is no hover, focus, active or disabled state. When the status changes the badge is replaced: "To review" becomes "Reviewed" once Dad sends feedback. When a count reaches zero the count badge is removed, not shown as "0".

Responsive behaviour

  • Badges never wrap (white-space: nowrap) and never truncate; keep labels to two or three words.
  • In a list row the badge sits before the action and the title wraps first. At 360px a row with "Reward to give" and a Manage button still fits.
  • On the phone tab bar the count badge is pinned to the top right of the icon.

Theming

Each variant reads a status pair: --color-{info,success,warning}-bg for the tint and --color-{status}-fg for the label and dot. Neutral uses --color-bg-subtle and --color-fg-muted. Count uses --color-danger-solid with --color-fg-on-danger. In dark mode the tints darken and the labels lighten, keeping every pair above 4.5:1.

Accessibility

Role and pattern

A plain <span> with text. No role: the status is read as part of the row. Where a count is updated without a page load, the number is announced by the page's polite live region, not by the badge.

Keyboard

KeyAction
TabSkips the badge; inside a nav link it is read as part of the link.

Focus

Never focusable on its own.

Labelling

The visible word is the label; colour and dot are extra cues (1.4.1). A count badge needs context, so it carries aria-label ("2 chapters to review"), and the nav link reads "Review, 2 chapters to review". The uppercase is CSS only; write the label in sentence case in the HTML so screen readers do not spell it out.

Motion

None. A badge that changes value does not pulse or bounce.

Touch

Not a target. A badge inside a link or tab bar item adds to that target; it never needs its own.

Content

  • One to three words, written in sentence case ("Reward to give"); the style uppercases it.
  • Say the state, not an instruction: "To review", not "Review now".
  • Use the same word for the same state on every page: "Reviewed" in the table, never "Done" elsewhere.
  • Counts are numerals ("2", "14"), never words.
