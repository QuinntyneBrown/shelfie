Component · Rewards

Picture list

Shows the pictures of one gallery reward as square thumbnails, marks the one that is featured, and lets Dad make another one featured, remove one, retry one that did not upload, or add another, up to six. It lives in the Add / edit a reward dialog in Settings.

Overview

Use the picture list for a thing that has several pictures, one of which stands for it. Today that is a gallery reward: its featured picture replaces the 🎁 on the Settings row and on Nia’s shelf card (see sticker and trophy).

The list does not upload anything itself. It shows the items its owner gives it, checks a chosen file’s type and size, and emits what Dad asked for. When editing a reward the dialog uploads, removes and features at once; when adding one it keeps the chosen files until the reward is saved. For one picture of a person use the photo picker; for a book’s cover use the cover picker; to choose one of several catalogue covers use the cover gallery. None of those can hold several pictures with a featured one, which is why this component exists.

Anatomy

  1. Label"Pictures (optional)"; it names the group.
  2. ThumbnailA square .picture-list__thumb, the picture cropped to fill it; its alt is "Picture N of M".
  3. Featured markA success badge "Featured", an accent ring around the thumbnail and the note "Shows on her shelf".
  4. RemoveA small icon button on the thumbnail’s corner, named "Remove picture N".
  5. Make featuredA small button under every other thumbnail, named "Make picture N featured".
  6. Add a pictureA small label.btn around a visually hidden input type="file".
  7. Help, status and errorThe rules, or "Uploading the picture…" in a polite live region; a .field__error for a refused file.

Up to 6. The featured one shows on Nia’s shelf. JPEG, PNG or WebP, up to 5 MB each.
  • Uploading sets aria-busy on that thumbnail, shows a spinner over it and "Uploading…" under it, and disables Add a picture, so a second upload never starts on top of the first. The other pictures stay usable.
  • Failed (network, server, or the server refusing the file) keeps the thumbnail with a danger border, "Didn’t upload." and Try again, which resends the same file. Remove drops it. Nothing else changes.
  • Invalid (wrong type, over 5 MB) is decided in the browser before anything is sent, and again by the server, with the same words as the photo picker.
  • Full: at six pictures Add a picture is disabled and the help says why; the server refuses a seventh too.
  • Removing the featured picture makes the oldest picture left featured; removing the last one leaves the list empty and the reward shows its 🎁 again.

Responsive behaviour

  • The grid is repeat(auto-fill, minmax(8.5rem, 1fr)): two columns in the 360px bottom sheet, three in the 30rem desktop dialog. Nothing scrolls sideways.
  • Remove sits on the thumbnail, so each column only has to fit one button under it.

Accessibility

Role and pattern

A role="group" named by its label, holding a list (ul named "Pictures") of thumbnails and a native file input inside a label, so "Add a picture" is the input’s accessible name. Help, status and error are tied to the input with aria-describedby; aria-invalid is set while an error shows.

Keyboard

KeyAction
TabEach picture’s Remove, then its Make featured or Try again, in reading order; then Add a picture.
Enter / SpacePresses the focused button, or opens the device’s file chooser.

Names and announcements

  • Every button names its picture: "Remove picture 2", "Make picture 2 featured", "Try picture 4 again". Thumbnails are "Picture N of M"; the Featured badge is text, so the state never rests on the ring colour.
  • "Uploading the picture…" is read from the status line and errors from the error line.
  • After Remove, focus moves to Add a picture; after Make featured it stays on the list, where the moved badge is read on the next picture.

Touch

Every button meets the 44px target through its padding. On phones the file chooser offers the camera.

Content

  • Label "Pictures (optional)". Help: "Up to 6. The featured one shows on Nia’s shelf. JPEG, PNG or WebP, up to 5 MB each." When adding: "Up to 6. They upload once the reward is added. JPEG, PNG or WebP, up to 5 MB each."
  • "Featured", "Shows on her shelf", "Make featured", "Uploading…", "Didn’t upload.", "Try again", "Add a picture".
  • Full: "That’s 6 pictures, the most a reward can have. Remove one to add another."
  • Errors: "Shelfie can’t use that file. Pick a JPEG, PNG or WebP photo." · "That photo is too big. Pick one under 5 MB."

Code

<!-- Angular (components library) -->
<sh-picture-list [pictures]="pictures" [max]="6" [disabled]="busy" [help]="help"
                 (picked)="add($event)" (removed)="remove($event)"
                 (featured)="feature($event)" (retried)="retry($event)" />

// pictures: { url: string; featured: boolean; state?: 'uploading' | 'failed' }[]
// Outputs emit the chosen File, or the index of the picture.
Class / inputEffect
.picture-list, .picture-list__gridThe group, and the auto-fill grid of thumbnails.
.picture-list__item--featured, --failedAccent ring; danger border and dimmed picture.
.picture-list__thumb[aria-busy]Spinner over a dimmed picture while it uploads.
.picture-list__removeThe Remove icon button on the thumbnail’s corner.
pictures, max, disabled, helpThe items; the most allowed (Add is disabled at it); everything disabled while the owner saves; the help line when no upload is running.
pickedEmits a chosen File once it passes the type and size checks; otherwise the list shows the error itself.
removed, featured, retriedEmit the index of the picture whose button was pressed.
