Wizard step

One purpose per screen: a step indicator, one big illustration, one question, one or two fields, one primary action, a quiet Back and a quiet Skip. The set-up wizard a parent sees once after signing up is five of these in a row.

Overview

A wizard step is a full page, not a dialog. It sits in the auth layout (centred card, logo, aurora) like sign-in and sign-up, so a parent who has just created an account stays in the same calm place. There is no top bar and no shell navigation: the only ways out are the step's own actions.

  • Step indicator above the card.
  • Illustration (img.wizard__art): one static SVG per step from assets/onboarding/, drawn in the stickers' style with pastel fills and a violet outline so it reads on both canvases.
  • One question as the h1, and at most one line under it.
  • One or two fields, or none on the welcome and All set steps.
  • Actions (.wizard__actions): one primary block button, an optional ghost Back under it, and "Skip for now" as a caption link below the card, outside it.

Responsive behaviour

  • The auth card is 26rem wide at most and full width under that, with the layout margin as gutter; the illustration is capped at 13rem so it never dominates a phone.
  • Actions stack vertically at every width: a block primary, then the ghost Back centred under it. There is never a row of two equal buttons.
  • Example chips (.cluster.wizard__examples) wrap and stay centred.
  • On a phone the whole step fits in one screen except the reward step, which scrolls past the chips; the primary action is always reachable with one thumb.

Accessibility

Structure and focus

  • Each step is its own page with one h1, the question. The step indicator is read before it as plain text.
  • On a step with a field, focus starts in the first field; on the welcome and All set steps it starts on the page, so the heading is read first.
  • The illustration has an empty alt: it repeats the question, never adds to it.
  • Back is a link and goes back; Skip for now is a link and leaves the wizard. Next and Add another are buttons.
  • Validation follows the forms pattern: on submit, errors on the fields with aria-invalid and aria-describedby, and a focusable summary when there is more than one field.

Keyboard

KeyAction
TabField(s), then Next, then Back, then Skip for now.
EnterIn a field, submits the step (Next).

Motion

The card scales in and the logo sways as on every auth page (auth page effects); the All set confetti runs once. All of it stops under reduced motion.

Content

  • The heading is a question to the parent, naming the child once she has a name: "What will Nia read toward?"
  • One line under the question at most, and only when it says something the field cannot: where the value shows up, or that it can be changed in Settings.
  • Buttons are verbs: Let’s go, Next, Add another, Go to my shelf. Never Continue, Submit or OK.
  • "Skip for now" is always the same words, always a link, always under the card.
  • Field rules and error wording are copied from the Settings dialogs that edit the same values, so a parent meets the same words twice.
