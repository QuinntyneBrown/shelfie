Empty and error states

An empty state is an invitation; an error state is an apology with a way forward. Both keep the page around them, say one thing, and offer one main action.

WCAG 2.2 AAStatus: stablePattern

Overview

Three situations, three compositions, all built from the empty state and error page components:

  • Empty: the request worked and there is nothing yet. Nia's shelf before her first book, Dad's book list before anything is added, the review queue when he is caught up. Accent icon, an encouraging title, one primary action.
  • Error in place (.empty--error): one region failed to load. It replaces only that region; the page header, breadcrumb and navigation stay. Danger icon, "[thing] didn’t load", "Try again" plus a way back.
  • Error page: the whole route cannot be shown: not found, grown-ups only, server error, offline. A large sticker, the title as the page's <h1>, one way home. The shell stays so navigation still works.

Responsive behaviour

  • The block is centred with its text capped at 36 characters, so it looks the same on a phone and in the middle of a wide desktop page.
  • Actions wrap and stay centred; on a 360px phone two actions stack.
  • Error pages keep the shell: Nia's top bar on reader routes, Dad's top bar and bottom tab bar on grown-up routes. The offline page also keeps the offline banner under the top bar.
  • Error pages add top space (--space-16) so the sticker sits in the upper third of the screen rather than under the top bar.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and links or buttons. In-place states use an <h2> under the page's <h1>; error pages make the title the <h1> and update the document title to match. Icons and stickers are aria-hidden.

Keyboard

KeyAction
TabReaches the primary action, then the second action.
EnterFollows the action. "Try again" re-requests the region without a page reload and returns to the skeleton.

Focus

When a region fails after the page has loaded, focus stays where it was. After "Try again" focus stays on the region's container until the content or the error returns. Error pages start at the top like any page; the skip link leads to the title.

Labelling

Action labels make sense alone: "Back to my shelf", not "Go back". The reference code is real text, so it can be read out and copied.

Contrast

Empty text on page
Empty icon on accent tint
Error icon on danger tint
Title on page

Motion

None. Empty and error states appear without animation, so a failure never looks like a celebration.

Touch

Actions are full buttons (44px, or 52px for Nia's "Add my first book") with 12px between them.

Content

  • Never blame the reader. "Nothing you did caused this and nothing was lost."
  • Say what is safe whenever data could seem lost: "Your answers are safe on the server."
  • Name Shelfie, not "the system": "Shelfie couldn’t reach the server."
  • Speak to whoever is reading. Nia's error: "Your shelf didn’t load". Dad's: "The books didn’t load". Forbidden speaks to Nia about Dad: "Ask him to sign in if he needs them."
  • No error codes for Nia; only the grown-up server error page shows a reference code.
  • See content and tone for the two voices.
