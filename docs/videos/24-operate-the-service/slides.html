Health answers, and the deploy waits for it

  • 200 {"status":"ok"} while the database is reachable
  • 503 {"status":"unavailable"} when it is not
if ! healthy; then
  echo "release $sha failed its health check" >&2
  journalctl -u shelfie -n 20 --no-pager >&2 || true
  if [[ -n $previous && $previous != "$release" ]]; then
    ln -sfn "$previous" "$root/current"
    systemctl restart shelfie
    echo "rolled back to $(basename "$previous")" >&2
  fi
  exit 1

Logs: one JSON line per request, in journald

  • requestId, method, route, status, durationMs
  • Never bodies, headers or URLs
sudo journalctl -u shelfie -f          # API
sudo journalctl -u caddy -n 100        # TLS, certificates, requests
sudo journalctl -t shelfie-backup      # nightly backups

Backups: nightly, verified, 30 days kept

# Nightly database backup at 08:15 UTC (03:15 or 04:15 in Toronto). Installed to /etc/cron.d by deploy.sh.
15 8 * * * shelfie /usr/local/bin/shelfie-backup 2>&1 | logger -t shelfie-backup
  • VACUUM INTO a dated file, integrity check, prune after 30 days
  • A copy of each in the backups blob container

Things to remember

  • Health answers ok or unavailable
  • Logs live in journald on the VM
  • The last three releases are kept, ready to roll back to
